# Тестовая VPN-админка

Стенд показывает снимок реальных данных; изменения доступны только в изолированной SQLite `/var/lib/vpn-admin-preview-test/snapshot.sqlite3` и не применяются к Xray, выдаче или исходным файлам. БД и `/opt/vpn-admin-read-test/snapshot.json` содержат секреты; не коммитить и не включать в секрет-free резерв исходников. Тестовые изменения переживают перезапуск службы и хоста; без отдельной закрытой резервной копии БД их нельзя восстановить после потери диска.

Пулы, имена подписок и узлов, порядок и основной выход, добавление и удаление подписки и замена URL сохраняются в тестовой БД. В карточке подписки находятся кнопки «Переименовать» и «Удалить»; удаление подтверждается вводом `DELETE`. Обновление и добавление подписки — моки: данные провайдера не загружаются; добавленная подписка не содержит узлов. Замена URL не меняет снимок соединений, по которому выполняются проверки. Удаление или снятие галочки согласует тестовую политику, но не боевой маршрут.

Проверки `general` выполняют HTTPS-запрос через отдельный временный Xray/Hysteria-клиент; Gemini и RU используют старый `route_probe.py`. Неопределённый результат не считается доказанным отказом. Результаты существуют в памяти. Старый Xray применяет leastPing; импортированный список не доказывает упорядоченный боевой fallback или активный выход.

Защищённый nginx Unix-сокет: `GET /api/subs`, `GET /api/routes`, `POST /api/routes/probe`, `GET /api/routes/probe/{job}`, `POST /api/mock`. POST требует точный Origin тестового домена и JSON. URL и ключи не выдаются ответом API. Не выставлять API на TCP и не привязывать mock-хранилище к боевым файлам.

Проверка из корня: `python -m pytest -q router/admin/test_read_api.py router/admin/test_preview_snapshot.py router/admin/test_mock_store.py`; UI smoke: `python -m router.admin.smoke_mock_browser` (зависит от Chromium, websocket-client и отдельного staging-каталога).
